Makefile targets (all must exist; `.PHONY`):

```
up:          docker compose up -d --wait --wait-timeout 90
down:        docker compose down -v --remove-orphans
test:        ./gradlew test  &&  uv run pytest
lint:        ./gradlew spotlessCheck checkstyleMain checkstyleTest  &&  uv run ruff check .  &&  uv run ruff format --check .
fmt:         ./gradlew spotlessApply  &&  uv run ruff format .  &&  uv run ruff check --fix .
rules-test:  @echo "not bootstrapped yet — see briefs/M2/M2-T3.md"; exit 1
```

(`&&` means: a failure in the first toolchain stops the target with a non-zero exit; do not hide failures behind `;`.) If checkstyle is not adopted, drop the two checkstyle tasks from `lint` and say so in `DEVIATIONS`; spotless is mandatory.

## Behaviour

1. Gradle root build applies a shared convention: Java toolchain 21, JUnit 5 (`useJUnitPlatform()`), Spotless with `googleJavaFormat()`, `-Werror` and `-Xlint:all` on `compileJava`. Every module inherits it; module build files stay at a few lines.
2. `services:*` apply the Spring Boot plugin (3.x) and depend on `libs:domain` and `libs:events`; `services:engine` additionally depends on `libs:rules`. No service depends on another service. Libraries are plain `java-library` modules.
3. Spring Boot and Spring dependency management versions are pinned in `gradle/libs.versions.toml` (version catalog). No other Java dependencies beyond JUnit 5, Spring Boot starter (web, test) and AssertJ.
4. `./gradlew test` on the empty tree succeeds. Modules with no tests must not fail the build.
5. Python: root `pyproject.toml` declares the `uv` workspace, `[tool.ruff]` (line length 100, target `py312`, rule sets `E, F, I, B, UP`) and `[tool.pytest.ini_options]` (`testpaths = ["workers"]`). Each worker has a smoke test asserting its package imports. `uv.lock` is committed. Dependencies: `pytest` and `ruff` only, as dev dependencies at the workspace root.
6. `uv` must install Python 3.12 itself (`uv python install 3.12` is acceptable in `docs/build.md`); do not require a system Python 3.12. The development machine has Python 3.11 on PATH; the build must not depend on it.
7. The Makefile runs under GNU make in Git Bash on Windows and under bash on Ubuntu (CI). Use `./gradlew` (not `gradlew.bat`) and forward-slash paths only. `.gitattributes` forces `eol=lf` for `gradlew`, `*.sh`, `Makefile`.
8. `.editorconfig`: UTF-8, LF, 2-space YAML/Kotlin, 4-space Java/Python.
9. `docs/build.md`: prerequisites (JDK 21, GNU make, `uv`, Docker), the five targets, and how to run one module's tests.

1. `./gradlew projects` → lists the seven leaf subprojects `:libs:domain`, `:libs:events`, `:libs:rules`, `:services:edge`, `:services:case`, `:services:engine`, `:services:review` and no other leaf module. The `:libs` and `:services` container nodes that Gradle creates for nested `include()` paths are expected. *(Reworded after review 2026-09-19: the original "exactly seven" contradicted the mandated `include()` block.)*
2. `make lint` → exit 0.
3. `make test` → exit 0; Gradle reports the seven modules built; pytest reports 2 passed.
4. `make fmt && git diff --exit-code` → exit 0 (formatting is idempotent on the committed tree).
5. Introduce a deliberately misformatted Java file in `libs/domain/src/test/java/` → `make lint` exits non-zero; remove it. Quote both results.
6. `uv run python -c "import docproc, llm_gateway"` → exit 0.
7. `git ls-files gradlew` shows the file and `git ls-files --eol gradlew` reports `w/lf` (LF in the working tree).
