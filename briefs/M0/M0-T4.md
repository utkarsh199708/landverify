## Goal

After this task, each of the four Java services boots as a Spring Boot application, answers `GET /health` with 200, has one contract test, runs as a container under compose, and `libs/events` holds the event envelope stub every later event will use.

## HLD references

- §4 System architecture — four services: Edge, Case service, Title engine, Review & report. "Each stage is a consumer that reads a case event, does one job, writes its result, and emits the next event; nothing calls the next stage directly."
- §5 End-to-end flow — the eight event names (`case.created`, `parcel.resolved`, `acquisition.complete`, `docs.gated`, `findings.emitted`, `review.needs_input`, `opinion.signed`, `report.sealed`); "Every transition is appended to the audit ledger with actor, timestamp, and the event payload hash."
- §9 Data & storage — "Event log (Kafka, compacted topics per case): every stage event with payload hash."
- §11 Observability — structured logs; CLAUDE.md "Logs: structured JSON, case id on every line".

Event envelope stub (`libs/events`), a Java `record` — field names and order are the contract for M1-T2:

```java
package com.titleengine.events;

public record EventEnvelope(
    String eventId,        // UUID v4, string form
    String eventType,      // one of EventType (below)
    String tenantId,
    String caseId,
    String producer,       // service name: edge | case | engine | review | docproc | llm-gateway | acquisition
    java.time.OffsetDateTime occurredAt,   // ISO-8601 with zone
    String idempotencyKey, // producer-chosen; duplicates with the same key are no-ops (M1-T2 enforces)
    String payloadHash,    // lower-case hex SHA-256 of the canonical JSON payload
    String payloadJson     // canonical JSON (sorted keys, no whitespace); typed payloads come in M1-T2
) {}

public enum EventType {
  CASE_CREATED("case.created"),
  PARCEL_RESOLVED("parcel.resolved"),
  ACQUISITION_COMPLETE("acquisition.complete"),
  DOCS_GATED("docs.gated"),
  FINDINGS_EMITTED("findings.emitted"),
  REVIEW_NEEDS_INPUT("review.needs_input"),
  OPINION_SIGNED("opinion.signed"),
  REPORT_SEALED("report.sealed");
  public final String wire;   // the string on the wire, exactly as above
  public static EventType fromWire(String wire);  // throws IllegalArgumentException on unknown
}

public final class PayloadHash {
  public static String sha256Hex(String canonicalJson);   // lower-case hex
}
```

The record's compact constructor rejects null or blank `eventId`, `eventType`, `tenantId`, `caseId`, `producer`, `payloadHash`, and rejects `eventType` not in `EventType`. Throw `IllegalArgumentException` with the field name in the message. No JSON library in `libs/events` in this task; serialisation helpers are M1-T2.

## Behaviour

1. Each service is a minimal Spring Boot app: `@SpringBootApplication`, one `@RestController` for `/health`, `application.yml` with `server.port` and `spring.application.name`. Spring Actuator is **not** required; a plain controller is fine and keeps the dependency set unchanged.
2. Logging: Logback JSON (`logstash-logback-encoder` is *not* in the catalog; use Spring Boot 3.4+ built-in `logging.structured.format.console=ecs` if the pinned Boot version supports it, otherwise plain console and note in `DEVIATIONS`). Case id on every line is M1; not here.
3. Dockerfiles: multi-stage, `eclipse-temurin:21-jre` runtime, non-root user, `HEALTHCHECK` on `/health`, `EXPOSE` the service port. Build context is the repo root (`docker build -f services/case/Dockerfile .`) so the Gradle build can see `libs/`.
4. `docker-compose.services.yml` is an overlay: `docker compose -f docker-compose.yml -f docker-compose.services.yml up -d --wait` builds and starts all four with `depends_on` on kafka, mongo, postgres (condition `service_healthy`) even though nothing uses them yet — the dependency graph is the contract for later milestones.
5. `docs/services.md`: what each service will own (one line each from HLD §4), ports, how to run one locally (`./gradlew :services:case:bootRun`), how to build the images.

## Acceptance criteria (each verifiable by a command or a named test)

1. `./gradlew test` → exit 0; the nine tests named above are reported as passed (`--info` or the JUnit XML under `build/test-results`).
2. `./gradlew :services:case:bootRun &` then `curl -sf localhost:8081/health` → `{"status":"UP","service":"case",...}`; repeat for the other three ports. Quote each body.
3. `docker compose -f docker-compose.yml -f docker-compose.services.yml up -d --build --wait --wait-timeout 300` → exit 0 (first image build may be slow; quote the time).
4. `for p in 8080 8081 8082 8083; do curl -s -o /dev/null -w "$p %{http_code}\n" localhost:$p/health; done` → four lines ending `200`.
5. Negative: `EventEnvelopeTest#rejects_blank_case_id` fails if the compact-constructor check for `caseId` is removed (do it, run, restore, quote).
6. `make lint test` → exit 0.
7. `docker compose -f docker-compose.yml -f docker-compose.services.yml down -v --remove-orphans` → exit 0.
