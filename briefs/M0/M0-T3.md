# M0-T3: CI with GitHub Actions

**Milestone:** M0
**Agent:** coder
**Branch:** `wave/M0-T3`
**Depends on:** M0-T1 (merged to main)

## Goal

After this task, every push and pull request to `main` runs `make lint` and `make test` for both toolchains on GitHub Actions with dependency caching, and the run is green on the current tree.

## HLD references

- §14 Tech stack — Java 21, Python via `uv`.
- §7 State rules pack — "tests are fixture cases that must pass before a pack version ships": CI is where that gate will live (M2-T3 adds `make rules-test`; leave a commented placeholder step).
- PLAN.md §1.6 — "Main is always green. Nothing merges red."

## Scope

## Interfaces (exact — copy, do not paraphrase)

Workflow:

```
name: ci
on:
  push:    { branches: [main] }
  pull_request: { branches: [main] }
concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }
jobs:
  java:    ubuntu-latest · actions/checkout@v4 · actions/setup-java@v4 (distribution temurin, java-version 21) · gradle/actions/setup-gradle@v4 (caching on) · run: ./gradlew spotlessCheck checkstyleMain checkstyleTest test --no-daemon
  python:  ubuntu-latest · actions/checkout@v4 · astral-sh/setup-uv@v3 (enable-cache: true) · run: uv python install 3.12 · run: uv sync --frozen · run: uv run ruff check . && uv run ruff format --check . · run: uv run pytest
  make:    ubuntu-latest · needs: [java, python] · same setup as both · run: make lint && make test
```

The `make` job exists so the Makefile itself is exercised in CI, not just its parts. If checkstyle was dropped in M0-T1 (see its `DEVIATIONS` in the merged commit / STATUS.md), drop the two checkstyle tasks here too.

Local mirror:

```
scripts/ci-local.sh   → runs exactly the commands the three jobs run, in order, exit non-zero on first failure
```

## Behaviour

1. All three jobs run on every push to `main` and every PR targeting `main`. No other triggers.
2. Caching: Gradle via `gradle/actions/setup-gradle`, `uv` via `enable-cache: true` keyed on `uv.lock`. Cache hit or miss must not change the result.
3. Timeouts: each job `timeout-minutes: 20`.
4. Permissions: `permissions: { contents: read }` at workflow level. No secrets are referenced (there are none yet).
5. `.github/dependabot.yml`: weekly updates for `github-actions`, `gradle`, `pip` (uv reads `pyproject.toml`), grouped, limit 5 open PRs each.
6. `docs/ci.md`: what runs, how to run the same locally (`scripts/ci-local.sh`), how to read a failure.
7. A commented-out step in the `make` job: `# make rules-test PACK=jh VERSION=<v>  — enabled by M2-T3`.

## Acceptance criteria (each verifiable by a command or a named test)

1. `python -c "import yaml,sys; yaml.safe_load(open('.github/workflows/ci.yml'))"` → exit 0 (use `uv run --with pyyaml python ...` if PyYAML is not in the workspace).
2. `bash scripts/ci-local.sh` → exit 0 on the current tree.
3. `actionlint` if available (`uv run --with actionlint-py actionlint` or the binary) → no errors. If actionlint cannot be obtained, say so.
4. Negative: temporarily break a Python test (`assert False`) → `bash scripts/ci-local.sh` exits non-zero at the python step; revert. Quote.
5. **Green run on `main`** — requires a GitHub remote. If the repository has no remote (check `git remote -v`), mark this criterion `NOT MET: no remote` and add to `QUESTIONS.md` under `M0-T3`: "Which GitHub org/repo should this push to?" Do not create a repository.
6. `grep -c 'secrets\.' .github/workflows/ci.yml` → `0`.
