## Interfaces (exact — copy, do not paraphrase)

Table (Flyway `V1__audit_ledger.sql`):

```sql
CREATE TABLE audit_ledger (
  seq           BIGSERIAL PRIMARY KEY,
  tenant_id     TEXT        NOT NULL,
  case_id       TEXT        NOT NULL,
  actor         TEXT        NOT NULL,
  action        TEXT        NOT NULL,
  occurred_at   TIMESTAMPTZ NOT NULL,
  payload_hash  CHAR(64)    NOT NULL,
  payload       JSONB       NOT NULL,
  prev_hash     CHAR(64)    NOT NULL,
  row_hash      CHAR(64)    NOT NULL UNIQUE,
  CONSTRAINT audit_ledger_hash_hex CHECK (row_hash ~ '^[0-9a-f]{64}$' AND prev_hash ~ '^[0-9a-f]{64}$' AND payload_hash ~ '^[0-9a-f]{64}$')
);
CREATE INDEX audit_ledger_case_idx ON audit_ledger (tenant_id, case_id, seq);

CREATE FUNCTION audit_ledger_deny() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN RAISE EXCEPTION 'audit_ledger is append-only (attempted %)', TG_OP USING ERRCODE = '42501'; END $$;
CREATE TRIGGER audit_ledger_no_update BEFORE UPDATE ON audit_ledger FOR EACH ROW EXECUTE FUNCTION audit_ledger_deny();
CREATE TRIGGER audit_ledger_no_delete BEFORE DELETE ON audit_ledger FOR EACH ROW EXECUTE FUNCTION audit_ledger_deny();
CREATE TRIGGER audit_ledger_no_truncate BEFORE TRUNCATE ON audit_ledger FOR EACH STATEMENT EXECUTE FUNCTION audit_ledger_deny();
```

Hash rule (the only definition; implement once in `LedgerHash`):

```
GENESIS_PREV_HASH = "0" * 64
row_hash = sha256Hex( prev_hash + "\n" + seq + "\n" + tenant_id + "\n" + case_id + "\n" + actor + "\n" + action + "\n"
                      + occurred_at as ISO-8601 in UTC with exactly 6 fractional digits, e.g. 2026-09-19T12:00:00.000000Z + "\n"
                      + payload_hash )
payload_hash = sha256Hex(canonical JSON of payload: keys sorted lexicographically at every level, no whitespace, UTF-8)
```

Java (package `com.titleengine.casesvc.ledger`):

```java
public record LedgerEntry(String tenantId, String caseId, String actor, String action,
                          OffsetDateTime occurredAt, String payloadJson)      // payloadJson: any valid JSON object
public record LedgerRow(long seq, String tenantId, String caseId, String actor, String action,
                        OffsetDateTime occurredAt, String payloadHash, String payloadJson,
                        String prevHash, String rowHash)
public interface LedgerAppender { LedgerRow append(LedgerEntry entry); }        // serialised: takes pg_advisory_xact_lock(hashtext('audit_ledger')) inside the tx
public record VerifyResult(long rowsChecked, boolean ok, OptionalLong firstBadSeq, Optional<String> reason)
public interface LedgerVerifier { VerifyResult verify(); }                      // walks seq ascending, recomputes every row_hash and checks prev_hash linkage and payload_hash
public final class LedgerHash { static String rowHash(...); static String payloadHash(String json); static String canonicalJson(String json); }
```

## Behaviour

1. `append` runs in one transaction: take the advisory lock, read the last row's `row_hash` (or GENESIS if none), compute `payload_hash`, insert with `prev_hash`, read back `seq`, compute `row_hash` — **note** `seq` is part of the hash, so either reserve `seq` with `nextval('audit_ledger_seq_seq')` before computing, or insert then update — updating is denied by the trigger, so use `nextval` first. Return the row.
2. `verify` streams rows ordered by `seq`; for each, recompute `payload_hash` from `payload` and `row_hash` from the fields; check `prev_hash` equals the previous row's `row_hash` (GENESIS for the first). First mismatch stops with `firstBadSeq` and a reason naming which of payload_hash / row_hash / prev_hash failed. Empty ledger → `ok`, rows=0.
3. Any `UPDATE`, `DELETE` or `TRUNCATE` against `audit_ledger` raises SQLSTATE 42501 from the trigger, for every role including the owner.
4. Flyway migrates on service start. The `/health` endpoint stays as in M0-T4.
5. No wall-clock inside the ledger code: `occurredAt` is supplied by the caller.
6. Canonical JSON: use Jackson to parse, then re-serialise with `ORDER_MAP_ENTRIES_BY_KEYS` and no indentation; numbers preserved as written where Jackson allows (document the limitation in `docs/ledger.md`: non-canonical number forms like `1.0` vs `1` are treated as different payloads).
7. Tests use Testcontainers `postgres:16` (Docker is available locally and on the Ubuntu CI runner). `CaseHealthContractTest` gets `@ServiceConnection` on a shared static container so the context boots. Container reuse is not required.
8. Dependencies (versions come from the Spring Boot BOM; add coordinates to `services/case/build.gradle.kts` only): `org.springframework.boot:spring-boot-starter-jdbc`, `org.postgresql:postgresql`, `org.flywaydb:flyway-core`, `org.flywaydb:flyway-database-postgresql`, `com.fasterxml.jackson.core:jackson-databind` (managed); test: `org.springframework.boot:spring-boot-testcontainers`, `org.testcontainers:postgresql`, `org.testcontainers:junit-jupiter`. Nothing else; no Spring Data.
9. `docs/ledger.md`: table shape, hash rule with a worked example (three rows with their hashes, generated by the test and pasted), how to run `ledger verify`, the tamper drill for M8.
