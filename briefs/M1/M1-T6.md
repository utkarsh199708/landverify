**Milestone:** M1
**Agent:** coder

## Goal

After this task, a library package gives every service one way to check that a principal may read or change a record of a given tenant, one abstraction to obtain a tenant's PII encryption key (file-backed in dev), and a data-driven role matrix for the six roles, with negative tests for cross-tenant access.

## HLD references

- §9 — "Multi-tenancy is by tenant id on every record plus a per-tenant encryption key for PII fields; no lender can ever see another lender's case, but the party name index is shared across tenants (names only)."
- §11 Security — "per-tenant PII keys; role-based access"; DPDP — "deletion = crypto-shred of the tenant key for that case".
- §2 Actors and CLAUDE.md roles: `lender-ops advocate runner transcriber ops admin`.
- §10 — advocate never sees a case from a state they are not empanelled for (state licence is an attribute checked here, though states are data).

Package `com.titleengine.domain.tenancy`:

```java
public enum Role { LENDER_OPS("lender-ops"), ADVOCATE("advocate"), RUNNER("runner"), TRANSCRIBER("transcriber"), OPS("ops"), ADMIN("admin"); wire(); fromWire() }
public record Principal(String subject, TenantId tenantId, Set<Role> roles, Set<String> stateLicences)  // stateLicences: advocate's licensed state codes, data not code; empty for other roles
public interface HasTenant { TenantId tenantId(); }              // implemented by persisted envelopes and by Case (Case already has tenantId(); do NOT edit Case — add the interface via a static helper `Tenancy.of(Case)` instead if Java forbids retrofitting; state which in DEVIATIONS)
public enum Action { CASE_CREATE, CASE_READ, CASE_REVIEW, FINDING_DECIDE, OPINION_SIGN, TASK_RETURN, TRANSCRIPT_SUBMIT, OPS_RESOLVE, TENANT_ADMIN, LEDGER_VERIFY }
public final class TenantGuard {
  public static void requireSameTenant(Principal p, TenantId recordTenant);   // throws CrossTenantAccessException (message never includes the other tenant id)
  public static <T extends HasTenant> T requireSameTenant(Principal p, T record);
}
public class CrossTenantAccessException extends RuntimeException
public class ForbiddenActionException extends RuntimeException
public final class RoleMatrix {
  public static RoleMatrix load();                                           // from classpath tenancy/role-matrix.properties
  public boolean allows(Role r, Action a);
  public void require(Principal p, Action a);                                // throws ForbiddenActionException unless some role of p allows a
  public SortedMap<Action, SortedSet<Role>> table();                        // for docs/tests
}
public interface TenantKeyProvider { byte[] keyFor(TenantId t); void shred(TenantId t); boolean exists(TenantId t); } // 32-byte AES-256 key; shred = key permanently unrecoverable
public final class FileBackedTenantKeyProvider implements TenantKeyProvider { public FileBackedTenantKeyProvider(Path dir, SecureRandom rng); }
   // one file per tenant: <dir>/<tenantId>.key, 32 raw bytes, created on first keyFor via rng; shred overwrites with zeros then deletes; keyFor after shred throws TenantKeyShreddedException
public final class PiiCipher { public static byte[] encrypt(byte[] key, byte[] plaintext, byte[] aad); public static byte[] decrypt(byte[] key, byte[] ciphertext, byte[] aad); } // AES-256-GCM, 12-byte IV prefixed, IV from SecureRandom passed in by caller for determinism in tests
```

## Behaviour

1. Domain records are not changed. "Tenant id on every record" is met at the persistence boundary: every stored document/row carries `tenant_id` (the ledgers already do) and every persistence envelope implements `HasTenant`. Record this in `docs/tenancy.md` as the rule later milestones follow.
2. `TenantGuard` compares `TenantId` by value. The exception message says only "cross-tenant access denied" plus the action context; it never echoes the record's tenant id.
3. `RoleMatrix.load()` fails fast if any `Action` is missing from the file or any role name is unknown (typo protection).
4. `FileBackedTenantKeyProvider`: key files are created with owner-only permissions where the filesystem supports it (POSIX); on Windows just create. `shred` is irreversible: after it, `exists` is false and `keyFor` throws. Never log key bytes.
5. `PiiCipher` uses `javax.crypto` only (no new dependency). The AAD is meant to be the case id so ciphertext cannot be moved between cases.
6. Nothing here reads the wall clock or uses randomness except via the injected `SecureRandom`.
7. Advocate state licence: `Principal.stateLicences` is a set of opaque codes; a helper `TenantGuard.requireLicensed(Principal p, String stateCode)` throws `ForbiddenActionException` if the principal has the ADVOCATE role and lacks the code. The library never contains a concrete state code.
8. `docs/tenancy.md`: the persistence-boundary rule, the role matrix table (generated from `RoleMatrix.table()` in a test and pasted), key lifecycle including crypto-shred, and what M7-T3 will add.
